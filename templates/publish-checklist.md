# 발행 전 체크리스트 — 전 항목 통과 없이는 배포하지 않는다

매 발행 직전에 산출물별로 돌리고, 결과를 `eval/YYYY-MM-DD.md`에 항목 번호별
통과/실패로 기록한다. 실패 항목은 고친 뒤 재검사한다. 기록이 없으면 그 발행은 실패다.
전부 2026-08-11~12 이틀간 실제 반려에서 나온 항목이다.

## A. 주어와 선별
- A1. 헤드라인의 주어가 제일기획(또는 계열 물량)인가? 경쟁사가 헤드에 있으면 실패
- A2. 경쟁사 항목이 2건 이하이고, 층(글로벌/침입자/국내)과 축(내수/해외)이 명시됐는가
- A3. 어제 실린 사실의 재편찬이 없는가? 오늘 뉴스가 없으면 quiet_day로 썼는가
- A4. 슬라이드 표지 헤드라인 = 당일 웹판 헤드라인인가? 덱에 전일 승계 슬라이드가 없는가
- A5. 경쟁사 단독 절 0건 — 경쟁사는 경쟁 지형 절(층×축 한 표) 안의 행으로만 다룬다.
  한 경쟁사의 해부·특집 절이 있으면 실패. 제일기획 심층 절이 경쟁사 절보다 앞·크게 배치됐는가
- F1. 절(`section.sec`)마다 전시물(`figure.exhibit`) ≥1 인가. `data-edition="digest"`면
  면제하되 그때 `section.sec`가 존재하면 즉시 실패. 제일기획 절은 강등 전 재전시 시도 필수.
  전시물 정의·강등 사다리는 `templates/exhibit-first.md` 참조. 우선순위는 A5 > F1 —
  전시를 위해 경쟁사 절을 만들지 않는다
- F2. 줄글 상한 — `li.news`의 `.s` ≤2(`details` 밖 기준), 절 도입 `<p>`의 `.s` 또는
  종결부호 ≤3. 초과는 경고, 요소 수 초과는 실패. 주석(`.ex-note`)에도 B7 전문 적용

## B. 언어
- B1. 내부 작업명 0건 — 화두판·발표판·특별판·확정판·보강/반증/전환/무관·"축으로 올린다"
- B2. 취재 과정 언어 0건 — "확인됐다"·"정정"·"미확인"·"새벽 기준"·"보도로만 알던"
- B3. 자기 참조 0건 — "어제의 화두"·"지난 호에서 말한"·"다음 호에서 다룬다"
- B4. 명사 조각 0건 — 본문·카드·슬라이드는 완전한 문장
- B5. 날짜는 날짜로 — "5.27"식 소수점 표기 0건
- B6. 숫자·인용은 원문 그대로, 파생값 0건, 등급(1차자료/보도/관찰) 표기
- B7. 선답 금지 — 헤드라인·리드는 사실형. 해석·인과("선행지표다", "신호가 켜졌다")는
  1차자료 근거가 있을 때만 단정하고, 없으면 한계를 같은 문장에 명시한다
  ("~와 맞닿은 숫자다 — 다만 그 관계가 공시로 확인된 바 없다"). 구조는 그날 재료가
  만든다 — 재료를 미리 정한 서사 틀에 끼워맞추지 않는다

## C. 판형
- C1. 이 호는 자기 URL인가? 전날 URL을 덮어쓰지 않았는가
- C2. 구조가 그날 재료를 따르는가? 전날 지면의 절 배치를 복사하지 않았는가
- C3. 다른 호 수록 자료는 본문 재수록이 아니라 링크 참조인가 — 단, 당일 뉴스의 직접 근거 표는 그날 호에 수록한다
- C4. 모든 링크·버튼은 실제로 동작하는가? 링크 없는 죽은 라벨이 없는가
- C5. 판형 바 게이트 통과 — `python tools/check_formats.py <웹판.html>` 종료코드 0.
  그날 만든 판형이 전부 `.fmtbar` 세그먼트로 있는가. 덱을 발행해 놓고 웹판에
  프레젠테이션 세그먼트를 안 넣으면 독자에겐 없는 것과 같다 (2026-08-11 실측:
  발표판을 발행했는데 웹판 fmtbar 에는 「라디오 버전」 하나뿐이었다).
  아카이브 호의 링크 없는 PPTX 라벨은 `--archive` 로 통과시킨다 (라벨의 「PPTX」도
  덱 세그먼트로 인정된다). 덱 요구의 정본은 **의도**다 —
  루틴이 EVAL 판정대로 `--expect-deck`(심층) / `--no-deck`(표준·간략)을 명시한다.
  플래그 없이 돌리면 파일 실존 추론으로 강등되며 그 사실이 출력에 남는다
  (이슈 #5: 파일 추론은 덱을 만들고 기록을 빠뜨린 날에 눈을 감는다)

## D. 기술
- D1. 표: thead·1열에 rowspan 0건, **4열 이상 표만** min-width 지정(스크롤 판형),
  3열 이하 표는 D6의 fit 판형(min-width 해제 — `class="fit"`)을 따른다, 모바일 폭에서 1열 고정 확인
- D2. 오디오: 컨테이너는 **MP4(AAC)** 로 넣는다 — **embed_radio.py 가 WAV/MP3 입력을
  자동 변환한다**(imageio-ffmpeg, SETUP §2 선택 의존성). 미설치·변환 실패면 도구가
  경고를 내고 원본 임베드로 강등되므로, 실행 로그에 「경고: imageio-ffmpeg 없음/변환
  실패」가 없는지로 판정한다. data:→blob 전환 코드 유지, 배속 −/+ 버튼 동작.
  WAV 를 그대로 실으면 호가 10MB 를 넘어 첫 렌더가 눈에 띄게 느리다 —
  같은 음성이 AAC 96k 로는 1/4 이다 (2026-08-12 실측: 7.42MB → 2.09MB, 길이·표본율 동일).
- D2b. **공개 배포 호에서는 아티팩트 안 다운로드를 포기한다.** 세 겹으로 막혀 있다
  (2026-08-11~12 실측): ① 뷰어 iframe 이 `sandbox="allow-scripts allow-same-origin
  allow-forms"` 라 `allow-downloads` 가 없다 ② 런타임의 `downloads` capability 를 쓰면
  플랫폼이 **공개 공유 자체를 거부**한다(deploy 422: "artifacts that use the downloads
  capability can't be shared publicly") ③ 그 capability 의 허용 확장자에 wav·mp3 가
  없다(gif png jpg jpeg webp mp4 webm txt json md). 그래서 저장 버튼은 넣지 않고,
  오디오가 필요한 독자에게는 `output/audio/YYYY-MM-DD.wav` 를 배포 묶음으로 보낸다 (E4)
- D3. 셀 줄바꿈 3줄 이하(모바일 스크린샷으로 확인)
- D4. 미정의 CSS 변수 게이트 통과 — `python tools/check_css_vars.py <웹판.html>`
  종료코드 0. var()가 참조하는 변수가 전부 정의돼 있어야 한다. 미정의 변수는 선언
  전체를 무효로 만들고 에러도 안 낸다 — 눈으로는 "좀 밋밋하네"로 넘어간다.
  다른 스킴에서 가져온 절을 붙일 때 특히 확인한다 (2026-08-12 바차트 투명 렌더,
  2026-08-11 라디오 블록·판형 바가 `--card`·`--line` 등 7개를 참조해 카드가 통째로
  배경·테두리 없이 떴다)
- D5. 바차트·게이지류는 라벨을 막대 위에 쌓는다 — 좌측 고정폭 라벨 열은 모바일 확대에서 글자가 세로로 쪼개진다
- D6. 표 판형 게이트 통과 — `python tools/check_tables.py <웹판.html>` 종료코드 0.
  3열 이하 표에 일괄 min-width 를 물리면 남는 폭이 전부 1열로 몰려 다음 열이 화면 밖으로
  밀린다(2026-08-12 모바일). 좁은 표는 fit(화면 폭 맞춤), 4열 이상은 스크롤 판형 — 눈이 아니라
  스크립트가 판정한다
- D7. 원장 정합 게이트 통과 — `python tools/check_ledger.py` 종료코드 0.
  ① okf/**·profiles/** 가 참조하는 F-### 개념이 전부 `okf/facts/` 에 실존(매달린 참조 0건)
  ② `status: deprecated` 인 개념이 index 「사실 — 유효」에 남아 있지 않음
  ③ index `generated.at` 이 facts 최신 파일·log.md 최신 항목보다 새것.
  JSONL 원장(`output/ledger/` — gitignore 대상)에만 쓰고 `okf/` 미러를 빠뜨리면
  배포본에 실체 없는 참조만 남고, 대체된 수치가 유효한 최신값으로 방송된다
  (2026-08-12 이슈 #7 실측: 매달린 참조 6건 + F-011 유효/대체 충돌 + 인덱스 08-10 정지).
  미러 + index 재생성은 JSONL 기입과 같은 실행에서 한 동작이다 (배포 정책 A안)
- D8. 호 크기 게이트 통과 — `python tools/check_size.py <웹판.html>` 종료코드 0.
  상한의 정본은 config 의 `tts.embed.max_html_mb`(기본 3.0MB — README 의 「호가 3MB
  안쪽」). 웹판은 오디오를 data URI 로 싣고 base64 는 원본의 4/3 로 부푸니
  「AAC × 1.34 + 지면」이 곧 호 크기다.
  **이 항은 편집 규율이지 공개 공유의 보증이 아니다.** 통과해도 E1 이 막힐 수 있다 —
  아래 E5 참조. 호를 작게 유지하면 스캔 가능성이 올라간다는 가정 위에 서 있다
- E5. **공개 전환 거절의 실체는 UI 문구가 아니라 API 응답이다** (2026-08-12 추적).
  Share → Anyone with the link 이 막히면 화면에는 이렇게 뜬다:
  "This version can't be shared publicly. Publish a new version or change the shared
  version, then try again." — **이 문구를 믿고 버전을 만지지 마라.** 헛수고다.
  같은 조작의 네트워크 응답은 `PATCH /api/frame/perm/<id>` → **409** 이고 본문이 원인을
  말한다: `{"reason":"unscannable", "error":"…public serving requires the served
  version's content scan to be dispatched (unscannable)"}`.
  공개 서빙은 **콘텐츠 스캔 통과가 전제**이고, 스캔이 안 걸리면 버전을 몇 개를 쌓아도
  안 풀린다. UI 가 제안하는 두 우회로가 소용없는 이유이기도 하다 — 새 버전도 같은
  내용이고, 공유 버전 콤보박스는 공개 전환 전까지 `disabled` 다.
  **거절되면 문구를 옮겨 적지 말고 개발자도구 네트워크 탭에서 이 PATCH 의 응답 본문을
  확인해 보고에 적는다.**

  실측 (2026-08-12, 같은 계정·같은 세션·같은 호를 오디오 비트레이트만 바꿔가며):

  | 호 크기 | 결과 |
  |---|---|
  | 1KB (순수 HTML) · 23KB (오디오 페이로드만 뺀 사본) | 공유됨 |
  | 0.61MB · 1.10MB · 2.14MB · 3.28MB | 전부 거절 |

  같은 페이지에서 **오디오 페이로드만 빼면 공유되고, 넣으면 거절된다** — `<script>`·
  `<audio>` 요소·CSS·구조·작은 data URI 는 통과본에도 그대로 있으므로 전부 원인이 아니다.
  1.10MB 호는 시간을 두고 재시도해도 거절돼 「스캔 착수 대기」 가설도 반증됐다.

  **그러나 크기가 원인이라고 단정하지 마라.** 반대 증거가 둘 있다:
  ① 공식 문서(code.claude.com/docs/en/artifacts «Page constraints»)가 밝힌 한계는
     **16 MiB** 이고, 콘텐츠 스캔·오디오·data URI 제한은 문서에 없다. 실제로 공유되는
     상한은 문서값보다 25배 이상 낮다 — 문서와 동작이 어긋나 있다.
  ② anthropics/claude-code#79824 (2026-07-21 open)는 **오디오도 큰 페이로드도 없는
     마크다운(Mermaid) 아티팩트**에서 같은 UI 문구를 보고했고, 보고자는 계정·세션
     레벨 문제로 결론냈다. 다른 실행 환경에서는 같은 종류의 호가 공유됐다는 보고도 있다.

  **결론: 원인 미확정.** 이 환경에서는 인라인 오디오를 뺀 호만 공개된다는 것이 실측이고,
  그것이 보편 규칙인지는 확인되지 않았다. 그러므로 **발행 후 E3(익명 개통 판정)을
  건너뛰지 마라** — 공유가 켜졌다고 화면이 말해도, 익명 GET 으로 본문이 오는지가 정본이다
- F3. PPTX 전시 슬라이드 노트에 `[EXHIBIT: 문서명|항목명]` 토큰 ≥1, 문서명이 웹판
  `data-doc`과 일치하는가. 라디오 대본에 `[EX: 문서명]` 참조 토큰 3~4개
- F4. 전시물 계약 게이트 통과 — `python tools/check_exhibits.py <웹판.html>` 종료코드 0.
  계약의 구체 값(필수 속성·자식 요소·`.ex-hl` 상한·도메인 화이트리스트·재전시 규칙)의
  **정본은 `templates/exhibit-contract.yaml`** — check 가 그 값을 읽어 판정한다.
  요지: 출처 data 속성+주석 3요소 전부 존재, 원문 파일 실존, 공식 소스만 전시,
  과거 전시물은 재전시 표기 강제
- F5. 게이트의 정직성 — 정적 게이트(check)는 **존재·계약만** 판정한다. 판형 일치·
  하이라이트의 질은 `eval/YYYY-MM-DD.md`의 수동 스팟체크(호당 전시물 1개 무작위 →
  원문 대조)로 분리해 기록한다. 출처 각주(`figcaption.ex-src`)에 원문 URL 의무

## E. 배포
- E1. 게이트 전부 통과 후 Share "Anyone with the link" ON — **그날 발행한 아티팩트 전부에**.
  웹판만 켜고 덱을 두면 fmtbar 링크가 남에게 404다 (2026-08-11 실측: 발표판이
  private 인 채로 남았다). 산출물 하나마다 한 줄씩 공유 상태를 기록한다.
  순서 주의(2026-08-12 확정): 공유를 켜는 순간 그 버전이 핀으로 잡히고, 그 뒤의
  수정은 핀 이동 거절(재현됨·원인 미규명)에 노출된다 — 그래서 「발행 직후」가 아니라
  「게이트 전부 통과 후」에 켠다 (routine 4b 발행 절차 ①~⑤). 공유 후에는
  `check_formats --check-links` 로 익명 개통을 판정한다
- E2. 공유 고정 버전 = 방금 발행한 버전 (번호가 가장 큰 것, 시간 표기로 고르지 않는다)
- E3. 로그아웃 상태에서 링크 열어 이번 호 헤드라인 문자열 확인
- E4. 당일 URL 기록 + 배포 메시지에 링크·WAV 첨부
