>

>    무엇이 생기는지(아침 루틴 + 본인 계정 아티팩트), 아래 요약을 근거로 짧게 설명한다.
>    **한 문단 상한 — 주절주절 금지.**
> 2. **헬스체크와 패널 준비를 조용히** — clone 전에 현 환경을 판별한다(`SETUP.md` 0-1~0-3

>    ① 지금 해주실 것(브라우저 로그인 — 필요할 때만, 패널을 띄워 놓고) ·
>    ② 동의가 필요한 것(무인 실행 권한 목록 — 유일한 질문) ·
>    ③ 고지(설치 위치·TTS 엔진·루틴 시각·reviewer 디폴트 — "바꾸려면 지금 한마디").
>    사용자가 링크에 조건을 달아 왔으면(예: 설치 위치) 묻지 않고 그 값을 쓴다.

>    로그인은 설치와 병렬이고, 발행·공유 직전에만 재판정한다. 이후의 역할 규칙은
>    저장소 루트의 `CLAUDE.md`(역할 계약)를 따른다 — 기본 역할은 설치자·운영자다.
>
> 사용자가 설치를 원하지 않으면 1의 소개에서 멈추고, 저장소를 수정하지 않는다.

매일 아침 Claude Code가 공개자료(DART·IR·업계 매체·글로벌 지주 뉴스룸)를 수집·검증해

- **API 키 없이 동작** — TTS 1순위가 로컬 엔진(Supertonic 3, 키·네트워크 불필요)입니다.

- 모든 사실은 원장(facts)에 등급(1차자료/증권사/보도/관찰)으로 등재, 발행 전 체크리스트
  게이트(A 주어 · B 언어 · C 판형 · D 기술 · E 배포 · F 전시물) 통과 — 일부는 스크립트가
  자동 판정합니다(`tools/check_*.py`)
- 웹판은 **전시물 우선** 편집 — 1차자료 원문 재현에 하이라이트·주석을 다는 방식이
  중심이고, 줄글은 상한이 있습니다 (`templates/exhibit-first.md`)
- 호마다 독립 아티팩트로 출판, 전날 호는 영구 아카이브

## 설치 — 링크 한 줄이면 됩니다

Claude Code(Max 플랜)를 열고 저장소 링크만 붙여넣으세요:

```
https://github.com/INTEGRITY2077/cheil-briefing-kit
```

Claude가 이 README의 진입 절차를 읽고 소개 → 헬스체크 → **합의 카드 한 번 →
무인 완주**로 진행합니다. 더 명시적으로 하려면:

```
https://github.com/INTEGRITY2077/cheil-briefing-kit 를 읽고 SETUP.md 대로 내 환경에 설치해줘
```

사용자가 하는 일은 카드 하나에 답하는 것뿐입니다 — 무인 실행 권한 목록에 동의하고
(유일한 질문), 필요하면 옆에 뜬 브라우저 패널에서 claude.ai 에 로그인합니다(설치가
도는 동안, 이미 로그인돼 있으면 이것도 없음). 설치 위치·TTS 엔진·실행 시각은 묻지
않고 디폴트를 고지합니다 — 바꾸려면 그 자리에서 한마디, 또는 링크에 조건을 달아
보내면 됩니다(예: "D 드라이브에 깔아줘"). 이후 의존성 설치 → 설정 생성 → 아침 루틴
등록 → 시험 실행 → 발행까지 질문 없이 스스로 진행합니다.

### 설치 후에 알아둘 것

- **시각은 합의값입니다.** 디폴트는 생성 07:00 / 배포 07:45이지만, 설치 때 정한 값이
  `config.yaml`의 `schedule`에 기록되고, 이후에도 Claude에게 "8시로 바꿔줘" 한마디로
  재설정됩니다. 문서에 적힌 시각은 전부 디폴트 예시입니다.
- **경로는 주입됩니다.** `routine-SKILL.md`의 킷 위치는 `{{KIT_ROOT}}` 플레이스홀더이고
  설치 때 실제 설치 경로로 치환됩니다. 나머지 경로는 전부 킷 루트 기준 상대경로입니다.
- **산출물은 당신 것입니다.** 브리핑은 당신의 claude.ai 계정으로, 당신의 아티팩트 URL로
  발행됩니다. `output/`(산출물)·`sources/`(전시물 원문)·`.env`·`config.yaml`은 커밋되지
  않으며(.gitignore), 저장소 push는 원작자·포크 전용입니다.
- **첫 TTS 실행 때** Supertonic 모델(실측 385MB)을 HuggingFace에서 한 번 내려받습니다.
  이후에는 오프라인에서도 동작합니다.
- **무인 실행 권한을 확인하세요.** 설치는 설치 위치에만 적용되는 허용 목록을
  `.claude/settings.json`에 만듭니다(SETUP 5절). 여기에는 킷의 파이썬 도구를 매일 아침
  묻지 않고 돌리기 위한 `Bash(python:*)`가 들어갑니다 — `rm`과 `git push`는 제외했습니다.
  넣기 전에 `tools/`의 파이썬 도구 전부(`tools/*.py`)를 한 번 훑어보시길 권합니다.

## 산출물

- **웹판**: 전시물(공시·IR 원문 재현+하이라이트+주석) 중심의 그날 뉴스, 상단에 라디오
  플레이어(기본 1.3× 배속, −/+ 조절). 오디오는 MP3(audio/mpeg)로 실어 호가 3MB 안쪽입니다.
  **아티팩트 안에서 저장은 안 됩니다** — 뷰어 iframe에 `allow-downloads`가 없고,
  런타임의 `downloads` capability를 쓰면 공개 공유 자체가 막힙니다. 오디오 파일이
  필요하면 로컬 `output/audio/YYYY-MM-DD.wav`를 배포 묶음에 첨부하세요
- **라디오**: 1인 낭독이 표준(Supertonic, 영역 전환 접속사 규칙). 2인 앵커·기자 판형은
  Gemini 엔진을 선택한 날만
- **프레젠테이션**: 웹판 전시물을 그대로 옮긴 슬라이드 + PPTX 보관본

## 지원 OS

Windows · macOS · Linux — Claude Code가 도는 곳이면 어디든. 도구와 의존성은 전부
크로스플랫폼입니다. **실측 검증: Windows 11 완료 · macOS(Apple Silicon, python 3.9) 완료**
(2026-08-14~15 맥미니 실측, 이슈 #33 — selftest·TTS·게이트 전종 + 앱 어포던스
(사이드패널 브라우저·scheduled-tasks·세션 크론) 전종. **macOS 고유 결함 0건**).
Linux는 미실측이니 설치 중 막히는 지점이 있으면 이슈로 남겨 주세요.
(config의 `sapi` 엔진만 Windows 전용 옵션이며 기본 사다리에는 포함되지 않습니다.)

설치 환경에 따라 갈리는 것은 OS가 아니라 **그 기기의 업로드가 한 번에 얼마나 나가는가**
입니다 — 아티팩트 발행은 호 전체를 한 번에 올리므로, 큰 호만 전송 중 끊기는 일이 생깁니다.

**「회선이 좁다」로 단정하지 마세요.** 2026-08-16 실측에서 맥미니가 2MB 를 57KB/s 로밖에
못 올리는 동안, **같은 공유기 아래 다른 PC 는 같은 순간 20MB 를 11.3MB/s 로 완주**했습니다.
그리고 그 맥도 **512KB 는 8.6MB/s** 로 올렸습니다. 회선도 랜카드도 아니었습니다.

**그리고 셰이퍼도 아니었습니다.** 같은 날 A/B/A 왕복으로 원인이 확정됐습니다 —
macOS 의 TCP 송신 버퍼 자동 확장(`net.inet.tcp.autosndbufmax`, 기본 4MB)이 범인이었고,
그 기기에 셰이퍼는 아예 없었습니다(dummynet 파이프 공백 · pf 카운터 73일간 0 ·
방화벽 비활성 · 공유기에 기기별 제한 기능 부재). 256KB 로 낮추자 10MB 가 0.88초에
**11.96MB/s** 로 올라갔고, 4MB 로 되돌리자 증상이 재발했습니다. 같은 OS·같은 기종에
보고된 **Tahoe ECN 업로드 스톨** 가설은 ECN 을 끈 채 버퍼만 오가게 해서 배제했습니다.

**왜 하필 이 기기에서 터졌는지는 아직 모릅니다.** 이 처방의 공개 선례는 1건뿐이고
(2026-06, 독일 DSL), 주류 튜닝 문서는 오히려 이 값을 **올리라**고 합니다. 이 킷이
말할 수 있는 것은 「그 기기에서 이 값이 증상을 켜고 껐다」까지입니다.

발행이 반복해서 끊기면 순서대로 보세요. **1~3 은 관리자 자격 없이 할 수 있고,
1 번이 원인의 성격을 곧바로 알려줍니다.**

1. **상행 사전판정 게이트를 돌립니다** (설치 시에도 자동으로 돕니다):

   ```bash
   python tools/check_uplink.py --target-mb 3.0
   ```

   크기 사다리(64KB→3MB)를 올리며 **버스트 붕괴인지 좁은 상행인지** 가려서 보고합니다.
   작은 것은 빠른데 특정 크기부터 무너지면 버스트 붕괴입니다 — 그 기기의 회선·랜카드는
   결백합니다. 무너지기 직전 크기가 **버스트 허용량**, 무너진 뒤 속도가 **지속
   상한**입니다 (맥 워커 실측: 1MB 까지 8.3MB/s, 그 위는 끊김, 30초 쉬면 회복).
   전 구간이 고르게 느리면 그때는 실제로 상행이 좁은 것이고, 게이트가 그렇게 말합니다.
   종료코드는 0 통과 / 1 못 올림 / 2 판정 불가입니다.
2. **macOS 라면 송신 버퍼부터 봅니다** — 유일한 확정 사례입니다. 읽는 데는 자격이
   필요 없습니다:

   ```bash
   sysctl net.inet.tcp.autosndbufmax
   ```

   `4194304`(4MB)이면 이것이 원인일 가능성이 높습니다. `sudo sysctl -w
   net.inet.tcp.autosndbufmax=262144` 로 낮추고 1 번을 다시 돌려보세요. 통과하면
   확정입니다. **재부팅하면 기본값으로 돌아갑니다** — 영구 적용은 부팅 시 실행되는
   LaunchDaemon 이 필요하고, 그건 이 킷이 아니라 그 기기의 설정입니다.
3. **총량인지 연결당인지** — 업로드 3개를 동시에 띄웁니다. 합이 단일과 같으면
   (실측 117KB/s vs 112KB/s) 그 기기에 **총량**이 걸린 것입니다.
4. **유선·무선을 동시에** — 두 인터페이스는 MAC 도 IP 도 다릅니다. 그런데도 합이
   단일과 같으면(실측 111KB/s) 원인이 **MAC/IP 가 아니라 기기 단위**라는 뜻이라,
   랜선을 바꾸거나 IP 를 바꿔도 소용없습니다. (송신 버퍼가 원인이면 이 결과가 나옵니다 —
   두 인터페이스가 같은 커널을 공유하기 때문입니다.)
5. **셰이퍼의 소재를 가릅니다** — 여기부터는 자격이 필요합니다.
   - 기기 쪽: `sudo dnctl list` · `sudo pfctl -sa` 로 dummynet 파이프를 확인 (macOS).
     Network Link Conditioner 를 켜둔 채 잊은 경우가 흔합니다.
   - 망 쪽: 공유기의 QoS·트래픽 관리에서 그 기기 항목을 확인. 또는 **휴대폰 핫스팟에
     붙여 1 번을 다시 돌려보세요** — 거기서 멀쩡하면 셰이퍼는 원래 망에 있습니다.
6. 위가 전부 정상인데도 느리면 **그때** 호 크기(`config.yaml` 의 `tts.embed`)를
   줄이세요 — 순서를 뒤집으면 멀쩡한 판형을 먼저 깎게 됩니다.
