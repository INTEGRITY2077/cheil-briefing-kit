# EVAL — 그날 브리핑의 깊이를 정한다

> 발행 여부를 정하지 않는다. 매일 나간다. 이 점수는 **분량과 깊이**를 정한다.
> 앞뒤 블록(오늘 일정, 다가올 일정)이 항상 채워지므로 0점인 날에도 방송은 나간다.

---

## 1. 점수

`profiles/<profile>.yaml` 의 `eval.scores` 를 쓴다. 아래는 제일기획 프로파일 기준이다.

| 항목 | 점수 | 세는 법 |
|---|---:|---|
| T1 신규 사실 | 5 | 공시, IR 자료, 증권사 리포트에서 새로 확인된 것 |
| **supersede 발생** | **4** | 기존 개념이 대체됨. 정정은 그 자체가 소식이다 |
| T2 신규 사실 | 2 | 경쟁사, 업계 매체, 고객사 뉴스 |
| T3 신규 사실 | 1 | 매거진, 자사 채널 |
| 마지막 심층 이후 경과일 | +1 / 일 | 조용한 주에도 결국 심층이 돌아온다 |

**세지 않는 것**

- 이미 방송한 개념 (`broadcast_at` 이 있음). supersede로 되살아난 것은 예외
- 일정(agenda). 매일 나가는 고정 블록이라 점수에 넣지 않는다
- 원장에는 적립했으나 확인이 덜 된 항목

## 2. 임계

| 점수 | 결과 | 산출물 |
|---:|---|---|
| **8 이상** | 심층 | 대본 4블록 + **아티팩트 갱신** + 오디오 |
| 3~7 | 표준 | 대본 3블록 + 오디오. 아티팩트는 그대로 |
| 3 미만 | 간략 | 대본 3블록(짧게) + 오디오. 원장만 적립 |

아티팩트는 심층일 때만 갱신한다. 매일 고치면 SOT 역할을 못 한다.

## 3. 계산 예시

**2026-08-10 (이 킷을 만든 날)**

| 항목 | 건수 | 점수 |
|---|---:|---:|
| T1 신규 (DART 손익·부문별·특수관계자, IR 자료 2건, 증권사 리포트) | 8 | 40 |
| supersede (AI 원인 서술, 분기/누적 서술) | 2 | 8 |
| T2 신규 (이노션 실적, 오픈AI, 글로벌 4사) | 3 | 6 |
| T3 신규 (매거진 10편, 자사 채널) | 2 | 2 |
| 경과일 | — | 0 |
| **합계** | | **56** |

→ 심층. 첫 실행이라 당연히 높다. 이후 평상시는 0~10 사이로 내려간다.

**조용한 날 예시**

| 항목 | 점수 |
|---|---:|
| 신규 없음 | 0 |
| 마지막 심층 이후 5일 | 5 |
| **합계** | **5** → 표준 |

신규가 없어도 경과일 가산으로 표준 분량이 나온다. 이때 `quiet_day` 항목을 쓴다.

## 4. 톤·문체 게이트

점수와 무관하게 매일 걸린다. 하나라도 걸리면 고친 뒤 다시 검사한다.

| 게이트 | 확인 |
|---|---|
| **G1** | `tone-guard` 금지 어휘가 있는가 → 대체하거나 해당 문장 삭제 |
| **G2** | 1차자료 근거 없는 문장에 단정 어미를 썼는가 → 완곡 어미로 |
| **G3** | 종합 판단·전망 문장이 있는가 → 사람 검토 전이면 삭제 |
| **G4** | 사내 부서·팀·개인을 지목했는가 → 조직 단위로 일반화하거나 삭제 |
| **G5** | 수치를 완화하거나 반올림했는가 → 원본 복원 |
| **G6** | `style-guard` genre `broadcast` 의 S1 규칙이 남아 있는가 |
| **G7** | 이미 방송한 개념을 다시 넣었는가 (정정 제외) |
| **G8** | 같은 일정을 네 번째로 내보내는가 |

G5가 가장 중요하다. **톤 조정은 서술의 문제이고 수치는 손대지 않는다.**

## 5. 사람이 걸어야 하는 지점

시스템이 자동으로 넘기지 않는 것 두 가지.

**종합 판단** — 나쁜 소식이 있는 날 시스템이 스스로 결론을 내면 안 된다. 클로징은 "앞으로 확인할 지표"까지만 쓴다. 그 이상은 사람이 검토한 뒤에만 나간다.

**검증 도장** — 주 1회, 그 주에 새로 생긴 개념만 훑고 `verified` 를 채운다. 15분이면 된다.

이걸 건너뛰면 6개월 뒤 아무도 확인하지 않은 수백 건 위에서 방송이 나간다. OKF 가 `generated` 와 `verified` 를 나눠 둔 이유가 이것이다.
